GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat は、作業がローカルでリアルタイムに進む間、ツール呼び出しやファイルの編集状況を表示します。エディターを離れずに各差分を確認し、個々の変更を採用または却下し、追加のプロンプトで会話を調整・拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントに依頼し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにします。新しい会話を始める代わりに、現在のセッションで作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各ステップが表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツールの操作を確認します。ファイルの読み込みや編集、実行を求められるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用 (ターミナルコマンドの実行など) に許可が必要な場合、エージェントは一時停止して **Allow** を表示します。許可する前にコマンドを確認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に変更内容の要約が表示されます。

## ライトモードを追加するようエージェントに依頼する

ハイコントラストモードができたので、同じ会話でライトモードの切り替えを追加します。前の作業を続けるため、エージェントは編集したコンポーネント、スタイルの方針、local storage を使った設定の保持方法など、既存のコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に、次のフォローアッププロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードと同様に、各編集を確認します。差分ごとに **Keep** または **Undo** を選びます。
4. たとえば、気に入らない方法でトグル UI をリファクタリングし始めた場合は、チャット入力欄の横にある **Stop** ボタンで作業を止め、要望を明確にするフォローアップメッセージを送信します。

> [!TIP]
> 作業中のセッションを方向付ける方が、最初からやり直すより早く進められます。フォローアッププロンプトを使って、調整 (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)、方針の修正 (「3 つ目のトグルは追加せず、ライトモードを既存の設定パネルに組み込んでください」)、範囲の拡張 (「両方のトグルにキーボードショートカットも追加してください」) を依頼できます。

## 作業ファイルをレビューする

変更を commit する前に、エージェントが編集したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更を stage して commit します。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで進行中のセッションを監視し、各ファイルの編集を確認して採用または却下し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- フォローアッププロンプトで、作業中のセッションを方向付けました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが行った変更をレビューします。
